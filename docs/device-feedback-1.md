# 実機フィードバックへの対応 — 1.0.0 (2)

## 確定した選択フロー

ユーザーは「1件を選ぶだけ。編集した後はFacetで選び直して更新」を選択した。

- 「共有する連絡先」からシステムの単一選択画面を開き、自分の連絡先を1回選ぶ。
- 継続的なContacts権限の要求、複数選択、許可した後の再選択を廃止。
- 選択した1件の対応項目をiPhone内に保存。写真・メモ・誕生日と他の連絡先は取り込まない。各QRに入れる項目は引き続き個別の明示的な許可が必要。
- 同じ連絡先の再選択は内容を更新し、公開項目の選択を保持。別の連絡先への変更では公開項目をすべてOFFにする。
- 編集・削除・OS権限取消は保存済みのコピーへ自動反映されない。「編集後は同じ連絡先を選び直す」と設定画面・Privacy Policy・アプリ説明で案内。
- リセットは連絡先のコピーと公開設定・QRを消去し、Watchへ空の状態を送る。その場で再び単一選択画面を開ける。
- build 1からの移行時だけ、すでに許可された選択済みIDを一度読み込む。アクセスできなければ手動選択へ進む。

[Apple: CNContactPickerViewController](https://developer.apple.com/documentation/contactsui/cncontactpickerviewcontroller) は権限を要求せず、選んだ連絡先だけを一度受け渡す。iOSに公開されたマイカード取得APIはないため、自動特定は行わない。

## Watch

QRを画面全幅の正方形で表示し、正方形の外側まで伸びていた白背景を削除。ページドットの領域も削除し、横スワイプは維持。読取に必要な4モジュールの余白は残す。46mmで仕事用の黒いQR領域は225pxから315pxへ拡大。42mmも確認。

## 検証

共通テスト22件、12言語の74キーと両アプリへの収録、正式版Xcode 27 (27A266a)によるRelease Archive・署名・テストデータ除外を確認。iPhone SE (第3世代) / iOS 26.3の使い捨てSimulatorで、システム単一選択、キャンセル、編集後の手動更新、再起動後の保持、非公開値の排除、アクセス権なしでの選択、リセット直後の再選択、元の連絡先削除後のコピー保持の4結合テストが成功。証跡は`work/contacts-20260915-161346`、`work/feedback/single-core.log`、`work/feedback/ready-preflight.json`。Watchの12言語×3プロフィールと日本語42mmの3枚、計39枚のQR読取を確認済み。実機の光学読取はTestFlightで再確認する。

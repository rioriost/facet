# 実装前プランレビュー

対象: 初回commit `810b11b`。2026-09-15にレビューし、implementation-plan.mdへ反映。

| 観点 | 指摘 | 採用する修正 |
|---|---|---|
| 技術的弱点 | WatchにはCoreImageがなく、vCardだけ送ってもQRを生成できない | iPhoneでモジュール化、共通SwiftUI描画。外部QRライブラリなし |
| 不足 | 「双方」の自動和集合は意図しない公開につながる | 独立した許可リスト、初期OFF、明示選択 |
| 不足 | カテゴリ選択だと私用電話まで混入し得る | 多値項目ごとのContacts identifierで選択 |
| 矛盾 | vCardとQRを両方Watchに保存する必要はない | QRモジュールのみ送信。復元可能な個人情報として保護 |
| 技術的弱点 | applicationContext受付と配達完了の混同 | UUIDをWatchから返して受信確認 |
| 不足 | 削除・権限取消・取得失敗後の旧QR | iPhone表示消去、空スナップショット、Watchローカル消去 |
| 制約 | オフラインWatchの遠隔取消は不可能 | ユーザー向け説明と最終同期日時 |
| 過剰設計 | 任意プロフィール数・バックエンド・第三者QR依存 | 初回は固定3プロフィール、標準フレームワークのみ |
| 不足 | UTF-8、vCard構文、密度の検証 | 境界単体テスト、実際のQR decodeとContacts parse |
| 優先順位 | 実機利用可能と実機合格は違う | まず漏洩防止・ビルド・Simulator、次に署名と実機の証跡 |

最終アイコン、全OS/端末テスト、GitHub公開、ストア提出は別の完了条件として追跡する。
